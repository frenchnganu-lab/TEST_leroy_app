# LEROY HOME — кабинет дизайнера

Тестовая кодовая версия Telegram Mini App для бота `@Leroy_app_bot`.
React + TypeScript → Python FastAPI → существующий Supabase PostgreSQL.
Make продолжает импортировать дизайнеров и начисления независимо от приложения.

## Интерфейс v0.2

Тёмный дизайн LEROY HOME CLUB по согласованному референсу: главная с интерьерным фоном, раздельными бонусами/вознаграждением, карточкой уровня, итогами проектов и баннером программы. Нижняя навигация, фильтры, карточки проектов, модальные окна. Подробная [техкарта](docs/UI_TECH_MAP.md).

Для текущего курса API теперь читает `reward_rules`. Если роль `cabinet_reader` создана ранее, выполните `sql/02_cabinet_rate_access.sql`. При первом подключении достаточно обновлённого `sql/01_cabinet_read_role.sql`. Веса уровня показаны только как пример в демо; реальные веса ещё не подключены.

## Что уже работает в коде

- Адаптивный интерфейс: обзор, проекты, последние 30 начислений, число приглашённых.
- Проверка подписи Telegram `initData` на сервере, ограничение возраста входа 1 час.
- Определение дизайнера только по проверенному `telegram_id`, без выбора чужого ID в запросе.
- Параметризованные запросы только на чтение к существующим таблицам `designers`, `projects`, `ledger_entries`.
- Явно включаемый демонстрационный режим с вымышленными данными; ошибки входа не переключают на демо автоматически.
- Docker-сборка: интерфейс и API обслуживаются с одного адреса. Отдельный хостинг React не требуется.
- Автоматические проверки GitHub Actions, локальные тесты авторизации.

Это тестовый кабинет. Баланс показывает сумму начислений, а не доступную выплату.
Все текущие записи SQL считаются тестовыми; фильтра test/live в текущей схеме нет.

## Локальный запуск

Требуется Python 3.12 и Node.js 22.

Терминал 1:

```bash
cd backend
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо предыдущей строки:
# .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
cp .env.example .env
# В PowerShell: Copy-Item .env.example .env
# Для просмотра макета установите в .env: DEMO_MODE=true
uvicorn app.main:app --reload
```

Терминал 2:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite, обычно http://localhost:5173.
Нажмите «Посмотреть демо». Вне Telegram реальные данные не открываются.

Проверки:

```bash
cd backend
python -m pytest -q
```

```bash
cd frontend
npm run build
```

## Подключение к существующему Supabase

1. Изучите и выполните `sql/01_cabinet_read_role.sql` в SQL Editor. Он создаёт отдельную роль чтения и политики, не пересоздаёт таблицы и не меняет начисления.
2. Установите для `cabinet_reader` уникальный пароль отдельным запросом в SQL Editor. Не сохраняйте пароль в репозитории и не присылайте скрин с ним.
3. Скопируйте host и port из Connect → Session pooler. Пользователь для pooler: `cabinet_reader.<project-ref>`, база `postgres`.
4. В секретах серверного хостинга задайте:
   - `BOT_TOKEN` — актуальный токен BotFather;
   - `DATABASE_URL` — строку PostgreSQL для новой роли, с URL-кодированным паролем и `sslmode=verify-full` (при необходимости добавьте путь к CA Supabase через `sslrootcert`);
   - `DEMO_MODE=false`.
5. Не используйте для кабинета суперпользователя `postgres` или роль импорта Make. Роль кабинета не может начислять деньги.

Роль читает строки всех дизайнеров, но доступна только Python-серверу. Сервер проверяет подпись Telegram и добавляет ID текущего дизайнера ко всем запросам. Пароль нельзя передавать браузеру.

### Привязка тестового пользователя

Поле `designers.telegram_id` должно содержать реальный числовой ID Telegram тестировщика, проверенный менеджером. Username и номер телефона не являются Telegram ID.
Назначайте ID только собственной тестовой карточке или с разрешения владельца. В SQL Editor можно выполнить параметризованный по смыслу запрос ниже, заменив обе заглушки:

```sql
-- Пример-шаблон, НЕ запускать без замены:
-- UPDATE public.designers
-- SET telegram_id = <проверенный числовой ID>
-- WHERE designer_id = '<ID собственной тестовой карточки>';
```

Публичного метода «выбрать designer_id и привязать себя» намеренно нет. Самостоятельная регистрация с проверкой номера/приглашения будет следующим этапом. Ввод числа на клиенте не считается идентификацией.

## Размещение и Telegram

1. На Docker-хостинге подключите этот GitHub-репозиторий и корневой `Dockerfile`.
2. Задайте перечисленные выше секреты. Порт берётся из `PORT`, по умолчанию 8000. Проверка здоровья: `/api/health` (проверяет сервер, не доступность БД).
3. Получите публичный HTTPS-адрес. Проверьте `/api/health`.
4. В BotFather выберите своего бота и задайте Menu Button / Web App URL полученным HTTPS-адресом (команда `/setmenubutton`).
5. Откройте бота в Telegram, затем кабинет через кнопку меню. Для привязанной активной карточки появятся её данные; для остальных — предложение обратиться к менеджеру.

Этот репозиторий сам по себе ещё не развёрнут. GitHub Pages не запускает Python; нужен серверный Docker-хостинг. Бот здесь используется для запуска Mini App, обработчик сообщений `/start` пока не реализован.
