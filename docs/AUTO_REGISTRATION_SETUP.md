# Автоматическая регистрация без менеджера

## Установка

1. В Supabase SQL Editor от postgres выполнить целиком
   `sql/04_automatic_registration.sql`. Предварительно должен быть установлен
   `sql/03_telegram_phone_binding.sql`. Скрипт можно применять повторно.
2. Render → Environment → добавить `AUTO_REGISTRATION_ENABLED` со значением
   `true`. Существующие BOT_TOKEN, DATABASE_URL, PUBLIC_APP_URL и
   TELEGRAM_WEBHOOK_SECRET сохранить. Save, rebuild, and deploy → дождаться Live.
3. Проверить в Telegram на номере, которого ещё нет в designers:
   /start → «Поделиться номером» → подтвердить контакт → ввести ФИО →
   «Всё верно» → «Открыть кабинет».

Существующий номер связывается со старой карточкой, если нет конфликта.
Новый номер создаёт активного дизайнера с уровнем bronze и ID TG-<uuid>.
Менеджер не подтверждает регистрацию. Имя указано пользователем; телефон
подтверждён через Telegram. Реестры проектов и денежных начислений не меняются.
Приветственный подарок этим этапом не начисляется: отдельно нужны сумма,
курс и однократная операция в журнале.

Функция доступна только серверной роли в закрытой схеме leroy_private.
Не добавлять эту схему к exposed schemas и не выдавать доступ anon/authenticated.
Неподтверждённые анкеты истекают через 24 часа и очищаются при обращении к функции.
«Отмена» удаляет текущую анкету. Перезапуск Render не теряет состояние анкеты.
Повторная доставка контакта/ФИО/подтверждения не создаёт второго дизайнера.

## Проверка в Supabase

```sql
SELECT designer_id, full_name, level_code, is_active, created_at,
       telegram_id IS NOT NULL AS telegram_linked
FROM public.designers
WHERE designer_id LIKE 'TG-%'
ORDER BY created_at DESC;
```

## Передача новых карточек в Google Таблицу через Make — отдельный следующий этап

Новые карточки сразу работают в кабинете через Supabase. Чтобы они попали в
рабочую Google Таблицу, нужен отдельный сценарий Supabase → Google Sheets.
Он ещё не настраивается автоматически этим кодом.

Алгоритм: выбрать TG-* дизайнеров → для каждого найти строку в Google Sheets
по точному designer_id → если отсутствует, добавить; если уже существует,
повторную строку не создавать. Телефон и ID записывать как текст, пользовательское
ФИО записывать в режиме RAW, чтобы таблица не исполняла формулы.
Не генерировать другой ID в Google Таблице и не переименовывать TG-* в Dxxx.
Существующий сценарий Google Sheets → Supabase должен сохранять telegram_id
и не перезаписывать уже созданную привязку пустым значением.

## Откат включения

Установить AUTO_REGISTRATION_ENABLED=false в Render и перезапустить.
Существующие карточки сохраняются, бот вернётся к привязке заранее внесённых
дизайнеров. Применённый SQL удалять не требуется.
