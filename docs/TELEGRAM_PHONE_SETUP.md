# Привязка Telegram по телефону

## 1. Подготовить Supabase

Сделайте резервную копию настроек роли при необходимости. Выполните целиком
`sql/03_telegram_phone_binding.sql` в Supabase SQL Editor от роли postgres.
Скрипт создаёт функцию в закрытой схеме leroy_private и разрешает только
серверной роли cabinet_reader вызывать её. Прямой UPDATE таблиц не выдаётся.
Схему leroy_private нельзя добавлять к exposed schemas Supabase.

Телефоны должны быть уникальными и записаны с кодом страны: +7..., не 8...
Пустой telegram_id допустим. is_active должен быть true.

**Make:** при обновлении дизайнеров не перезаписывать telegram_id пустым
значением из Google Sheets. Привязкой управляет сервер; перепривязка делается
менеджером после проверки. Этот этап не начисляет приветственные бонусы.

## 2. Добавить настройки в Render

Открыть сервис → Environment → Edit. Существующие BOT_TOKEN и DATABASE_URL
оставить. Добавить две переменные:

- PUBLIC_APP_URL: https://test-leroy-desigher.onrender.com
- TELEGRAM_WEBHOOK_SECRET: собственная случайная строка 40–64 символа
  (латинские буквы, цифры, _ и -). Не использовать пароль базы или токен бота.

Секрет вводить только в Render, не в чат и не в GitHub.
Нажать Save, rebuild, and deploy. При запуске сервер сам вызывает setWebhook
с секретным заголовком и адресом /api/telegram/webhook.
Это заменяет существующий webhook этого бота. Не подключать того же бота
одновременно через Telegram Watch Updates в Make или через polling.

Без TELEGRAM_WEBHOOK_SECRET обработчик выключен; существующий кабинет работает.
При удачной настройке в логах: Telegram onboarding webhook configured.

## 3. Проверить лично в Telegram

Открыть личный чат с ботом, отправить /start. Нажать «Поделиться номером» и
подтвердить передачу контакта. Если номер есть ровно у одной активной карточки,
бот покажет «Открыть кабинет». Перезапустить кабинет, если он уже был открыт.

Проверить свою карточку в Supabase: telegram_id теперь заполнен.
Повторная отправка собственного контакта не меняет привязку и не начисляет бонусы.
Чужой/пересланный контакт, неактивная карточка, неизвестный номер и конфликт
привязки не дают доступ. Для таких случаев бот предлагает обратиться к менеджеру.
Смена номера Telegram не переносит существующую привязку автоматически.

## Диагностика

- Нет ответа на /start: проверить `Telegram onboarding webhook configured` в Render;
  правильность BOT_TOKEN и обеих новых переменных; отсутствие другого webhook.
- database_or_delivery_error: проверить применение SQL и работоспособность базы.
  Секреты и сырые исключения намеренно не печатаются.
- Профиль не найден: сверить международный формат телефона и is_active.

## Проверки разработки

`cd backend && python -m pytest -q`

Unit-тесты закрывают секрет webhook, чужие/пересланные контакты, ошибки базы,
отказ привязки, повторную доставку и команду регистрации webhook. Проверка
SQL на реальной базе и сквозной вход выполняются отдельно после установки.
